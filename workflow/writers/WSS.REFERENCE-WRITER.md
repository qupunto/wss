# Writing the reference record

> **A procedure, not a skill** — see [`WSS.WRITERS.md`](WSS.WRITERS.md). Sole writer of `WSS.record.reference`, per [`WSS.OWNERSHIP.md`](../WSS.OWNERSHIP.md).

**Sole writer of `WSS.record.reference`.** Everything else in this workflow that
needs it changed calls this procedure; who owns what is
[`WSS.OWNERSHIP.md`](../WSS.OWNERSHIP.md), and what this
file may and may not hold is
[`WSS.RECORD-CONTRACT.md`](../WSS.RECORD-CONTRACT.md), which is the
authority when this file and that one disagree.

Resolve the path from `.claude/WSS.WORKFLOW.json`. Without a manifest the fallback is
in [`WSS.MANIFEST.md`](../WSS.MANIFEST.md) — **say which you used.**

**`WSS.record.reference` is often a list of paths rather than one**, and a project
may map its `README.md` into it. That mapping is the manifest saying the README
*is* the project's reference material, which makes it this procedure's — not an
ordinary file anyone may edit, and not `--wss-docs`' to place by tier.

## Never take over a README that was not offered

**The fallback is `WSS.README.md`, and that is the whole safety property.** A
project with no manifest gets a file that announces itself; it does not get its
`README.md` quietly rewritten. A fallback of `README.md` would mean adopting the
suite hands a hand-curated landing page to a procedure that rewrites it — the
shape of change nobody consents to, because nothing in the tree says it has
happened.

So: **write `README.md` only where the manifest names it.** An explicit mapping
is consent. A fallback is not, and inferring one from "the project has a README"
is the fault this section exists to name.

**When you create `WSS.README.md`, its first line says so**, before any content:

```markdown
> **Autogenerated.** This file is `WSS.record.reference`, maintained by the
> Workflow Secretary Suite. Edits here are overwritten. The project's own
> landing page is `README.md`.
```

A reader who lands in the file learns it is not theirs without going anywhere
else, which is the point — a marker only in the manifest is a marker nobody
reads. Where the manifest *does* map `README.md`, put the same note there
instead, worded as maintenance rather than as autogeneration: that file is
usually still read by humans as a landing page.

## What this record holds

**Current state.** The stack and its versions, how the pieces fit together, the
data model, directory layout, and the conventions the project has actually
adopted.

Two things it never holds:

- **Decision history.** Why the stack is this stack belongs in
  `WSS.record.decisions`, written by `--wss-log`. This file says what is true now; a
  reader wanting the argument has somewhere else to go.
- **Runtime rules.** Auth, ownership, state transitions, error statuses — those
  are `WSS.record.behaviour`'s, written by
  [`behaviour-writer`](WSS.BEHAVIOUR-WRITER.md). The line between the two is
  *what the system is* against *what the system does*, and when a subject sits on
  it, put it where a reader would look for it and leave a pointer in the other.

## Two kinds of caller, and they want different amounts

This is why the record has its own primitive rather than living inside `--wss-docs` —
[`WSS.OWNERSHIP.md`](../WSS.OWNERSHIP.md)'s split test. A third route,
`--wss-reference` (`reference`), exists to bring a conversation-settled fact
here directly; it arrives shaped like the dispatched correction below — one
fact, one named file and section.

### A dispatched one-line correction

From `--wss-check`, `--wss-full-check`, `--wss-start` or `--wss-stocktake`. Scope is **the section
the finding names, and nothing else.**

1. **Re-verify against source before writing.** A dispatched finding is a
   hypothesis, not an instruction —
   [`WSS.OWNERSHIP.md`](../WSS.OWNERSHIP.md#the-inspector-writes-nothing).
   Hand the disagreement back rather than writing a correction that is itself
   wrong.
2. **Fix what was asked**, and report anything else you noticed rather than
   widening the job.

### A structural change

From `--wss-start` Phase 6 after a schema or architecture change, or from `--wss-adopt`
when a project's shape was established for the first time.

1. **Read the source of truth.** For a data model that is the schema and its
   migrations, not a summary of them.
2. **Rewrite only the affected sections**, re-reading the source for each.
3. **Count nothing from memory.** "N seeded locales", "three services", "the four
   entry points" — every such figure is a claim that decays silently. Run the
   command that produces it, or write the command instead of the number:
   [`WSS.RECORD-CONTRACT.md`](../WSS.RECORD-CONTRACT.md#the-mutable-claim-rule).

## Negative claims need the grep that would disprove them

"Nothing else reads this key", "no endpoint enforces X" — run the search first
and, where it is cheap, leave the command in the file rather than the verdict.
[`WSS.RECORD-CONTRACT.md`](../WSS.RECORD-CONTRACT.md#negative-claims) is the
rule; this record is where it bites hardest, because a reference is exactly what
a later reader trusts instead of checking.

## Where the code disagrees, the code is right

Fix the record and **report the drift you found**.

## Authorization

**None of its own.** Its grant is whatever the caller was granted, and it confers
nothing — [`WSS.OWNERSHIP.md`](../WSS.OWNERSHIP.md) has the rule. It does not
commit; the caller does that when its own flag allows.
